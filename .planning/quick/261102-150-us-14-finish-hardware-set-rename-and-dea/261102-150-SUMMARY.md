# Quick Task 261102-150: US-14 hardware set rename / deactivate Summary

Rename, deactivate and reactivate for hardware sets across Flask, React and tests, with the deactivate rule enforced inside the atomic write filters (not just a prior read).

## Commits
- 88f8c96: server (routes, data layer, active guards, tests)
- see `git log` for the client commit (HardwareSetAdmin, inactive card state, tests)

## What shipped
- POST /api/hardware/rename (unique-index backed, 409 hardware_set_name_taken) and POST /api/hardware/set_active (409 hardware_set_in_use with checkedOut).
- `_ACTIVE_GUARD = {"$ne": False}` in both checkout write filters and the addReservation filter; legacy docs without `active` read as active. Check-in and release carry no guard.
- Deactivate filter uses `checkedOut: {$not: {$gt: 0}}` so a missing field cannot spin the loop.
- Client: HardwareSetAdmin (Rename / Deactivate / Reactivate), Inactive badge and note, Check Out disabled while Check In stays usable, card key now `_id` so rename does not remount.
