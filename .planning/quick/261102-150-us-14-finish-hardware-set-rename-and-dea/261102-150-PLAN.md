<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to Flask routes | Request bodies are untrusted JSON; projectId, userId, hwSetName, newName, and active can be any JSON type |
| route to MongoDB | Values that reach a filter must be plain strings or a validated boolean |
| concurrent writers | Checkout, request, deactivate, and rename can interleave between a read and a write |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-261102-01 | Tampering | /api/hardware/rename, /api/hardware/set_active | mitigate | assertProjectMember rejects non-string projectId and userId; normalizeHwSetName rejects non-string names before any filter is built; setHardwareSetActive requires isinstance(active, bool). Covered by tests posting {"$ne": ""} as newName and non-boolean active values |
| T-261102-02 | Elevation of Privilege | New routes | mitigate | Wrappers call assertProjectMember first, and both routes are added to test_api_contract.py ROUTES, which proves 403 with no writes for non-members and unknown projects |
| T-261102-03 | Tampering | Duplicate names under concurrent rename | mitigate | Rely on unique index uniq_project_hwSetKey and catch DuplicateKeyError; renameHardwareSet ensures the index first; race-tested with RacingClient |
| T-261102-04 | Tampering | Checkout or request landing on a deactivated set | mitigate | _ACTIVE_GUARD in the checkout and addReservation write filters, and checkedOut guard in the deactivate filter; race-tested in both directions |
| T-261102-05 | Denial of Service | Retry loops in _adjustCheckedOut and setHardwareSetActive | mitigate | Lost checkout writes re-read and raise HardwareSetInactiveError; the deactivate filter uses $not $gt so an absent checkedOut cannot cause a permanent non-match |
| T-261102-06 | Denial of Service | Members stranded holding units on an inactive set | mitigate | Checkin filter and removeReservation carry no active guard; tested by check-in and release while inactive |
| T-261102-07 | Spoofing | Body-supplied userId identity | accept | Existing behavior on every hardware route; moving routes to the session is separate planned work and is out of scope here |
| T-261102-08 | Repudiation | Any member can rename or deactivate a set, with no audit trail | accept | No per-project roles exist in this PoC, and both actions are reversible |
</threat_model>
