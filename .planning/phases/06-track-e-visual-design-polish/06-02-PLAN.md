**1. `client/scripts/check-contrast.mjs` — the gate (new file).**

Write a Node ES module using only the standard library, runnable as `node client/scripts/check-contrast.mjs` from the repository root. Resolve the stylesheet path relative to the module's own location via `import.meta.url`, not via `process.cwd()`, so the command works regardless of the caller's directory.

It reads `client/src/index.css`, parses every `--name: value;` declaration in the `:root` block into a map, and resolves a value that is itself a `var()` reference by following it once. Implement sRGB relative luminance per WCAG 2.1: divide each channel by 255, apply the linearisation branch at the 0.03928 threshold (`c/12.92` below, `((c+0.055)/1.055) ** 2.4` at or above), then weight `0.2126 R + 0.7152 G + 0.0722 B`. Contrast is `(Llighter + 0.05) / (Ldarker + 0.05)`.

Hold an explicit table of pairs to check, each naming a foreground token, a background token, a required ratio, and a short role label. The required set: ink on bg at 4.5; ink on surface at 4.5; ink-muted on surface at 4.5; ink-muted on surface-soft at 4.5 (the table header row); on-ink on ink at 4.5 (the primary button and the active filter pill); on-ink on the primary-button hover fill at 4.5; the focus-ring colour on bg at 3.0 (a non-text indicator); danger-fg on danger-bg at 4.5; each of the four freshness foreground/background pairs at 4.5; and both reservation-entry foreground/background pairs at 4.5.

Print one line per pair giving the role, the two hex values, the measured ratio to two decimals, the requirement, and a pass or fail word. Exit non-zero if any pair is below its requirement **or if any named token cannot be resolved** — an unresolvable name must fail loudly, because a silent skip is exactly how a renamed token turns this gate into a no-op that reports success.

Deliberately do not check decorative rules and dividers. `--color-stone` against `--color-surface` measures about 1.29:1, and WCAG 1.4.11 does not require 3:1 of a structural divider that identifies no state. Gating it would make `06-UI-SPEC.md`'s own locked border value unsatisfiable. Record that exclusion in a comment at the top of the pairs table so nobody later "fixes" the gate by adding it.

**2. `client/src/index.css` — derive the two freshness triples that must change.**

The past-best-by state already uses the danger triad `06-UI-SPEC.md` hands down, and the no-date state's existing warm-neutral values sit correctly in the alabaster register — point the expired tokens at the danger triad and leave the unknown triple's values as they are. What must actually be derived are the fresh and use-soon triples.

Derive `fresh` as a soft sage pairing anchored to `--color-sage`: a light desaturated sage background, a deep sage-green foreground, and a mid-tone sage border. Derive `use-soon` as a soft amber in the same muted register: a warm light amber background, a deep amber-brown foreground, and a mid-tone amber border. Both must read as muted and earthy — `06-UI-SPEC.md` §Color forbids saturated or neon values for these — and both foreground/background pairs must clear 4.5:1 under the script from step 1. Iterate the values until the gate passes; that is the point of building the gate first.

Commit the derived values as **literal hex**, not as `color-mix()` expressions. The UI-SPEC offers `color-mix()` as a way to *find* a value; a literal is what makes the shipped value auditable by the script and by a future reader. Do not ship Phase 5's fresh background `#DCEFD8` or its expiring background `#FAEBC8` unchanged — the first is a cooler mint than the sage register requires and the second predates the new surface; both need re-deriving against white rather than parchment even where the hue family is close.

**3. `client/src/index.css` and `client/src/App.css` — retire the migration aliases.**

Sweep `App.css` so every reference to `--color-rule` and `--color-rule-soft` becomes `var(--color-stone)`, every reference to `--color-accent` becomes `var(--color-ink)`, and every reference to `--color-danger` becomes `var(--color-danger-fg)`. Then delete all four alias declarations from `:root`. Order matters: deleting an alias while a reference survives produces no build error, only an invisible fallback to the property's initial value.

While in that sweep, restyle the shared button rule set (`.restock-form button`, `.item-actions__row button`, `.reservation-entry__release`) into the botanical language: pill radius, `var(--color-surface)` fill, `var(--color-stone)` border, `var(--color-ink)` text, and a hover that raises the border to the terracotta accent. Keep the existing `:focus-visible` and `:disabled` behaviors intact — the disabled rule in particular must keep applying, since those controls now render inside a dialog and `06-UI-SPEC.md`'s UI Considerations table requires that styling not regress.

Derive `--color-terracotta-deep` as a darkened terracotta that carries `--color-on-ink` at 4.5:1 or better, add it to `:root`, and point `.button-primary`'s hover fill at it. The base `--color-terracotta` measures 3.32:1 against white, which is why plan 06-01 deliberately left that hover pointing at ink rather than shipping an unmeasured value. Keep the base token declared — it remains the correct choice for a border or a non-text accent.

Add no colour literal to `App.css` and introduce no gradient. Do not record any removed token name in a source comment; the acceptance criteria negative-grep both files.

**4. Record the measured ratios.**

Run the script and keep its output — plan 06-03 Task 2 transcribes the real numbers into the design document, replacing Phase 5's now-stale parchment-era measurements. Paste the full output into this task's section of the plan SUMMARY so the numbers survive even if the script is later changed.

**1. `client/src/App.css` — the shared state panel.**

Add `.state-panel` as `background-color: var(--color-surface); border: var(--rule-width) solid var(--color-stone); border-radius: var(--radius-lg); box-shadow: var(--shadow-card); padding: var(--space-xl); display: flex; flex-direction: column; align-items: center; gap: var(--space-lg); text-align: center;`. Add `.inventory-table__empty` as `padding: var(--space-3xl) var(--space-xl); text-align: center; color: var(--color-ink-muted); font-style: italic;`.

**2. `client/src/components/Project.js` — the loading return.**

Replace the bare loading paragraph with a `.state-panel` containing the spinner element, marked `aria-hidden` so assistive technology reads the message rather than announcing a decorative graphic, and a paragraph reading exactly `Loading inventory` followed by a single horizontal-ellipsis character U+2026 — one character, not three periods.

**3. `client/src/components/Project.js` — the error return.**

Replace the error return with a `.state-panel state-panel--error` containing a paragraph and a Retry button. The paragraph carries the prefixed copy from the Copywriting Contract: the word "Couldn" then an apostrophe entity then "t load your inventory." then a space then the interpolated `{error}` value. Use the HTML apostrophe entity rather than a bare quote character, matching how `AmbiguityNotice` already writes contractions in this file.

Give the Retry button `type="button"`, the `.button-primary` className, and the unchanged `onClick={loadInventory}`. This is the Phase 5 UI-review finding: the button previously had no className at all, so it inherited nothing — no fill, no border, no hover, no focus ring — and did not read as clickable. Reusing `.button-primary` gives it the same pill affordance as the toolbar action and pulls in the shared focus and disabled rules.

Render `{error}` as a plain JSX child — it originates from a server response and must keep React's escaping (threat T-06-01).

**4. `client/src/components/Project.js` — the empty state inside the table.**

The empty state belongs inside `InventoryTable`, not as a sibling that replaces it: `06-UI-SPEC.md` §5 requires the header row to stay visible above the message so the user can still see what the columns are and can still change the location filter. When `rows` is empty, render a `<tbody>` holding one `<tr>` with a single `<td colSpan={5} className="inventory-table__empty">` reading exactly `Nothing stored here yet.`

The same treatment covers both cases the UI-SPEC names — a household with no items at all, and a location filter matching zero rows — because `InventoryTable` receives the already-filtered array and cannot tell the two apart. That is the intended behavior, not a shortcut.

**5. Confirm the disabled styling survived the move into a dialog.**

Task 1 preserved the `:disabled` rule during the button restyle; verify here that it still matches the selectors those controls use, and that `.button-primary` is included in the disabled selector list. Change no component to achieve this — it is a CSS selector coverage check, and `Checkout.js` and `RestockForm.js` stay untouched.
